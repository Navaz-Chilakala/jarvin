# Jarvin product status

> **This page is a snapshot from 6 November 2026 and is partly out of date.** Since then the chat model changed to `qwen3:8b`, listening became an explicit microphone switch with a required "Hey Jarvin" wake phrase, and a speech detector, push-to-talk, auto-resume, background mode and document creation were added. For the current state read the [implementation tracker](JARVIS-IMPLEMENTATION.md), the [capabilities list](JARVIN-CAPABILITIES.md) and the [technical guide](JARVIN-TECHNICAL-GUIDE.md).

Snapshot: 6 November 2026. This is the current Electron/TypeScript product in `jarvin/jarvin`. The original Project JARVIS brief supplied in chat is a target, not a claim that every requested capability is complete.

## What Jarvin is today

Jarvin is a Windows user-session app with an Assistant view, a Code view, and a small draggable floating companion. It uses local Ollama for chat and screen understanding, a local speech recognizer, and a local speaking voice. The main process owns the agent, tools, permissions and task records; the hidden main window keeps voice and task activity running while the pet floats. It is **not yet a Windows service** and does not operate after the app quits, the PC sleeps, or the session locks.

The user's current machine has 24 GB RAM, an RTX 5050 laptop GPU with 8 GB VRAM, `qwen3.5:4b` for chat/tools, `qwen3-vl:4b-instruct` for vision, and Qwen3-ASR 0.6B int8 for final English transcripts. The voice model runs on the CPU so Ollama can use the GPU. These are local choices, not requirements for every installation. The user's saved speech setting is English, high sensitivity, offline-only, and Qwen3-ASR.

## User decisions carried into the product

- Listening (changed on 11 and 12 November at the user's request): the microphone is off until switched on, and with it on only speech that starts with "Hey Jarvin" is acted on; "stop" works without the name. The earlier decision, "speak normally with no wake phrase", was dropped after background sound was heard as requests.
- The pet should remain visible and draggable while the main app is minimized; clicking it returns to the app.
- Screen tasks should use the visible screen and actual mouse and keyboard. Chrome should visibly open and navigate when requested.
- Routine desktop actions can run without repeated approvals in the selected automatic mode; destructive actions still have a fresh-consent rule.
- Voice should interrupt speech and an active model reply. Mostly English is the recognition priority.
- Phone control comes later.

## What is built but still limited

1. **Speech quality:** Better local ASR is integrated. Voice settings include an in-memory microphone check that shows raw recognizer output, basic cleanup, input level, speech threshold, Silero's separate speech/no-speech verdict and decode time without sending a request or saving a recording. The backend requires threshold-level audio frames to cluster in a short span, and automatic Qwen requests use a bundled Silero VAD model to check the completed clip before ASR. The listener's startup room calibration was shortened from one second to about 0.4 seconds; speech immediately after opening the microphone can still be missed. Silero could reject quiet words or add latency, and its effect on the user's “random words” symptom is not measured. The user's physical microphone still needs comparison of spoken phrase versus transcript. The recognizer waits roughly 650 ms for silence before final decode and is not streaming final ASR. Listening to the user's interruption while Jarvin speaks works in earlier generated-audio tests; acoustic echo rejection is unknown.
2. **Visual control:** Jarvin can capture a selected display, locate a field in that image, and type into its pinned foreground window. It can send a one-step tab or window traversal shortcut and inspect the resulting screen. The model does not infer continuously on every frame. The primary-display sampler and one-use click checks limit stale actions. Broad “click that paragraph/logo/window” reliability, recovery after unexpected popups, mixed-DPI multi-monitor layouts and wrong-window prevention need a measured real-app suite. A native Windows Graphics Capture stream is not integrated. See [the TeamViewer comparison](VOICE-DESKTOP-RESEARCH.md#teamviewer-comparison-for-windows-control) for the screen/input distinction and Windows permission limits.
3. **Autonomy:** Agent loops, background commands and task records exist, yet multi-step success still depends on model tool choice. The pet can now pause a running request and open its saved draft for review, but it cannot safely resume the exact step automatically because some mouse or keyboard actions may already have happened. Routines are natural-language steps, not guaranteed workflows. Long tasks survive hiding/minimizing, not app exit or sleep. There is no service-backed scheduler or durable automatic resume.
4. **Browser and documents:** Research and visible Chrome flows work on checked cases. Form filling, authenticated sites, cross-tab control, citation accuracy across many sites, OCR and creation/editing of office files need acceptance checks and implementation.
5. **Permissions:** Automatic mode reduces prompts for routine actions, but some actions still ask by design. The pet and Privacy dialog have a persistent Pause observation control for Jarvin's built-in capture paths. The microphone keeps listening. Per-app/window rules now block full-screen capture when excluded windows are visible, filter window lists and reject input to excluded targets. These are not validated on the user's live apps and do not cover arbitrary external MCP servers or shell commands.
6. **Release:** The current installer rebuild failed with `spawn UNKNOWN` during NSIS uninstaller creation. The prior and partial artifacts were moved to `.old`, `.stale` or `.failed` names so they are not mistaken for the current build. The update feed in `package.json` is a placeholder. A release needs a working installer build, clean-profile install, launch, upgrade, uninstall, and model download.

## Next acceptance milestones, in order

1. **Real voice session:** On the user's microphone, compare exact spoken phrases to raw/final transcripts in quiet, fan noise and while Jarvin speaks. Measure end-of-speech → transcript → first spoken reply p50/p95, false activations and interruptions. Fix capture/VAD/echo issues shown by that data.
2. **Real desktop task set:** Run repeatable tasks in Chrome, File Explorer, a document editor and a native Windows app: locate paragraph/logo, click, type, scroll, observe outcome, recover from a changed window. Record success/failure and wrong-window events. Validate the new per-window/app exclusions and close any paths they miss.
3. **Durable task execution:** Separate persistent coordination from the interactive agent or explicitly narrow the product to “runs while Jarvin is open.” Add resumable job state, controlled scheduling and restart recovery before claiming background autonomy after exit.
4. **Browser/document workflows:** Validate research citations, form filling and document creation/editing on representative cases, using visible UI where requested and dedicated integrations where more reliable.
5. **Release hardening:** Clean-profile installer/model-download test, signed builds, real update endpoint, rollback and privacy/security review.
